## 📝 備註
- **心跳機制**：所有 Agent 預設每 10 秒發送一次心跳，30 秒未更新視為離線。
- **通訊頻道**：`aibro:hotline` (Pub/Sub), `aibro:agents:*` (Key-Value)。
- **依賴**：需要 `redis` npm 套件和 `redis-cli` 工具。

## 📚 Agents & Sessions 研究報告
- **核心發現**：
  - **Agent** = 獨立大腦 (Workspace + Auth + Sessions)。
  - **Session** = 對話記憶 (Per-peer / Per-channel-peer)。
  - **多 Agent 路由**：Bindings 決定誰處理訊息 (Peer > Account > Default)。
  - **跨機通訊**：OpenClaw 原生**不支援**分布式 Agent 互通 (需 Redis 或自建聊天室)。
- **工具**：`sessions_send` 是同一 Gateway 內 Agent 通訊的橋樑。
- **來源**：研讀 10+ 篇官方文檔與 GitHub Issues。

## 🌐 Google Skills 自研決策
- **決策**：**不直接使用** 現有第三方 Google Skills (如 `gmail-skill`, `gog-skills`)。
- **原因**：
  - **安全**：避免 OAuth 憑證洩漏風險。
  - **整合**：需深度整合 AIBRO Redis 神經網絡 (心跳、熱線)。
  - **彈性**：自研可完全掌控功能與更新節奏。
- **實作路線**：
  1. **AIBRO Gmail Guardian**：監聽新郵件，Redis 推送通知。
  2. **AIBRO Calendar Concierge**：行程預警，智能調度。
  3. **AIBRO Drive/Docs Manager**：文件協作。
- **技術棧**：Node.js + Google API (OAuth2) + Redis Pub/Sub。
