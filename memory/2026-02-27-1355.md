**AgentToAgent 是去中心化的：**

```
┌─────────────────────────────────────────────────────┐
│ 每台機器都開 Gateway + AgentToAgent 服務             │
├─────────────────────────────────────────────────────┤
│                                                     │
│  p43e-laptop:9090  ◄─── token ───►  msi-laptop:9090 │
│      │                                      │       │
│      │          互相連接，平等peer            │       │
│      │                                      │       │
│  你的機器:9090  ◄─── token ───►  其他機器      │
│                                                     │
└─────────────────────────────────────────────────────┘

每台機器都要：
1. listen: { host: "0.0.0.0", port: 9090 }
2. peers: { 其他機器的 endpoint + auth }
```

**Token 獲取流程：**

```bash
# 1. 在每台機器上生成自己的 token
openclaw agenttoagent token generate --name p43e-laptop

# 2. 產生的 token 會顯示在螢幕上或存到檔案
# 把這個 token 複製給其他要連接你的機器

# 3. 其他機器連接時用你的 token
# {
#   "endpoint": "https://p43e-laptop:9090",
#   "auth": { "type": "bearer-token", "token": "<複製來的token>" }
# }
```

**所以流程是：**
1. 每台機器 `openclaw agenttoagent token generate` 產生自己的 identity token
2. 把機器的 endpoint + token 分享給要互連的機器
3. 每台機器在 `peers` 中填入其他機器的資訊

**AgentToAgent 的真實面貌（當前版本）：**

```json
// 這是正確格式
tools: {
  agentToAgent: {
    enabled: false,  // 預設關閉
    allow: ["home", "work"],  // 允許通訊的 agentId 列表
  },
},
```

**它不是 P2P 跨機器架構！**

```
┌─────────────────────────────────────────┐
│ 同一個 Gateway 內的多個 Agent 通訊      │
│                                         │
│  • Agent: home  ◄────►  Agent: work     │
│  • 共享同一個 Gateway                   │
│  • 同一台機器上運行                     │
└─────────────────────────────────────────┘
```

**你之前看到的那個複雜格式**（protocol/grpc、listen、peers、capabilities）是 **未來規劃**，還沒實装。

**當前可用的多機器方案：**

| 方案 | 狀態 | 說明 |
|------|------|------|
| AgentToAgent | ✅ 已有 | 同 Gateway 多 Agent 內部通訊 |
| Bridge Protocol | ⚠️ Legacy | TCP JSONL，被 WebSocket 取代 |
| 跨機器通訊 | ❌ 還沒 | 需要等新版本或用其他方式（如 n8n webhooks） |

**你想實現的是「跨機器協作」還是「同機器多 Agent 分工」？** 🦞
